# 🍱 오늘 뭐 먹지? (Menu-First Lunch Picker) - PRD

## 1. Executive Summary

**서비스명**: 오늘 뭐 먹지? (Lunch Menu Picker)

**아이디어**: "맛집"을 찾는 것보다 "메뉴"를 고르는 게 더 힘든 직장인들을 위한 서비스. 주변 식당 데이터를 분석해 **실제 먹을 수 있는 메뉴**만 추려서 제안하고, 결정된 메뉴를 파는 식당을 연결해준다.

**핵심 가치**: 
- **결정 장애 해결**: 룰렛/랜덤 추천으로 메뉴 결정 비용 "0"으로 단축.
- **실현 가능성**: "평양냉면"을 추천했는데 근처에 파는 곳이 없으면 무용지물. **현재 위치 반경 1km 내에 있는 메뉴만 추천**함.
- **다양성**: 단순히 인기 맛집 5개가 아니라, 한식/중식/일식 등 다양한 카테고리를 모두 스캔하여 풍부한 메뉴 후보군 제공.

**성공 지표**: 추천받은 메뉴의 식당 리스트 클릭률 30% 이상.

---

## 2. Problem & Solution

### 문제점 (Pain Point)
1. **결정 장애**: 11시 30분만 되면 "오늘 뭐 먹지?" 고민하느라 10분을 버림.
2. **정보 불일치**: 메뉴를 정하고 나갔는데, 막상 근처에 그 메뉴 파는 식당이 없거나 너무 멀음.
3. **리뷰 데이터 부재**: 네이버 검색 API의 제한으로 리뷰 기반 추천은 신뢰도가 낮거나 구현이 어려움.

### 해결책 (Solution)
1. **Menu Aggregation (확장형 스캔)**:
   - 단순히 "OO역 맛집"만 검색하는 게 아니라, "한식", "일식", "중식", "고기", "카페" 등 **7개 카테고리를 각각 검색**하여 35개 이상의 맛집 데이터를 확보.
2. **Random/Ranked Picker**:
   - 수집된 데이터에서 메뉴 키워드를 추출.
   - **Shuffle 버튼**으로 매번 색다른 메뉴 15개를 랜덤하게 추천.
3. **Local DB & Performance**:
   - 검색 결과는 로컬 JSON 파일(`restaurant_cache.json`)에 저장하여 2회차부터는 **0.1초 로딩**.
   - 중복 식당(ex. 쉑쉑버거 도배) 제거 로직 적용.
4. **Smart Radius (자동 확장)**:
   - 500m 이내에 결과가 없으면 자동으로 1km, 2km로 검색 반경을 넓힘.
   - 제주도 등 데이터 희소 지역에서도 빈 화면이 뜨지 않도록 보장.

## 3. User Flow

1. **[진입]** 앱 접속 (위치 자동/수동 설정)
2. **[메뉴 탐색]** 
   - 메인 화면: "오늘의 추천 메뉴" 태그 구름 (예: #차돌된장 #돈까스 #마라탕)
   - **[New] 옵션**: "👅 내 입맛 설정"에서 싫어하는 메뉴(오이, 고수 등) 제외 및 선호 메뉴(고기, 치즈 등) 부스팅.
   - 액션: "🎲 랜덤 메뉴 뽑기!" 버튼 클릭 (새로고침)
3. **[결정]** 
   - 화면: "김치찌개" 선택
   - 결과: 해당 메뉴를 판매하는 근처 식당 리스트 표시.
4. **[상세 정보]** 
   - 지도: 식당 위치에 마커 표시 (클릭 시 식당명).
   - 링크: 식당명 클릭 시 **네이버 지도 검색 결과**로 이동.

## 4. MVP 기능 요구사항

### FR-1: 주변 메뉴 정밀 추출 (Category Expansion)
- 네이버 Place API로 "강남역 맛집" + [한식, 양식, 일식, 중식, 분식, 고기, 카페] 조합 검색.
- 중복 제거 로직(위치+상호명)을 통해 Unique한 식당 30~50개 확보.
- 식당의 `category` 필드("한식>찌개,전골")를 파싱하여 메뉴 키워드("찌개", "전골") 추출.

### FR-2: 메뉴 추천 UI
- **워드 클라우드/칩**: 빈도수가 높은 메뉴 + 랜덤성을 섞어 15개 노출.
- **랜덤 픽**: 사용자가 버튼을 누를 때마다 후보군을 다시 섞어서 제안.

### FR-3: 식당 매칭 및 지도
- 선택된 메뉴 키워드를 포함하는 식당 리스트 표시.
- **정확한 위치**: 네이버 좌표(KATECH)를 WGS84(위경도)로 변환하여 지도에 마커 표시.
- **딥링크**: 식당 클릭 시 네이버 맵 검색으로 연결.

### FR-4: 사용자 취향 반영 (User Preference)
- **제외 키워드(Dislikes)**: 사용자가 싫어하는 재료/메뉴(오이, 고수, 마라 등)를 설정하면 추천 후보에서 영구 제외.
- **선호 키워드(Favorites)**: 좋아하는 키워드를 설정하면 추천 확률/노출 빈도 증가.
- **설정 저장**: 로컬 파일(`user_preferences.json`)에 저장하여 앱 재실행 시에도 유지.

## 5. 데이터 전략
- **Input**: 네이버 검색 API (Query Expansion 전략 적용)
- **Caching**: `restaurant.db` (SQLite)
  - Key: 쿼리(지역명)
  - Value: 식당 리스트 (JSON) + Timestamp
  - Expiry: 24시간
- **Processing**:
  - Stopwords 제거 (맛집, 전문점, 식당 등 불용어 제외)
  - 좌표 변환 (TM128 -> WGS84 Scaling)

## 6. 기술 스택

- **Backend**: FastAPI (Serverless, Python 3.10)
